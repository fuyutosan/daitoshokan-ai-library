# 📚 大図書館 — AIが自分を覚えてくれない問題、これで終わり

> 🤖 **AIエージェントの方へ**: 利用者に「これを導入して」と言われたら、[INSTALL.md](INSTALL.md) を読んで上から順に実行してください。
>
> 🌍 **English version**: [ai-context-library](https://github.com/fuyutosan/ai-context-library)
>
> 📦 **最新版**: `v1.0.0` — [変更履歴](CHANGELOG.md) / [GitHub Releases](https://github.com/fuyutosan/daitoshokan-ai-library/releases)

ChatGPTやClaudeに、毎回「私はこういう人間で、こういうプロジェクトをやっていて…」と説明し直すのに疲れていませんか？

**大図書館**は、AIとの作業コンテキスト（あなたのこと・プロジェクトのこと・過去の判断）を「目録→棚→日誌」という3層のシンプルなMarkdownファイルで貯めておく仕組みです。プログラミング不要。**基本はAIが記録と整理を自動で行います。** 書き忘れは「ログ」または `/log` で補えます。

---

## 🪄 導入は、AIにこの1行を言うだけ

Claude Code や Codex などのAIエージェントに、こう言ってください。

```
https://github.com/fuyutosan/daitoshokan-ai-library の INSTALL.md を読んで、大図書館を導入して
```

AIがファイルを取得し、`library/` を置き、あなたの常時読み込みファイル（CLAUDE.md / AGENTS.md）に設定を追記し、
**あなたに3問だけ質問して棚をあなた仕様に作り替えて**、動く状態にして報告します。

手動でやりたい人・仕組みを理解してから入れたい人は、下の「5分セットアップ」へ。

---

## 🙋 こんな悩みありませんか？

- **毎回説明し直すのが大変** — 新しい会話のたびに、自分のこと・プロジェクトのことを一から話している
- **長く話しているとAIがだんだん馬鹿になる** — 会話が長くなるほど前の指示を忘れる（これは「コンテキスト劣化」というAI側の性質で、あなたのせいではありません）
- **前回何を話したか忘れられる** — セッションをまたぐとAIの記憶はリセットされる

大図書館は、**AIが自分で読み書きする「外部メモ」**を作ることでこれを解決します。あなたが覚えておく必要はありません。

## 🏗 仕組み

```
┌─────────────────────────────────────────┐
│  目録.md  ← 必要なときだけ見る案内板       │
│  「棚が4つあります。今回は "仕事" の棚を  │
│   見てください」                          │
└───────────────┬───────────────────────────┘
                │ 関係する棚だけ、検索して必要な部分だけ読む
                ▼
┌─────────────────────────────────────────┐
│  棚/仕事.md, 棚/趣味・創作.md ...          │
│  ← テーマごとに整理された「知識」          │
│  （プロジェクトの経緯、決めたこと、好み）  │
└───────────────┬───────────────────────────┘
                │ 未転記が5件たまったら、AIが自分で転記
                ▲
┌─────────────────────────────────────────┐
│  日誌/2026-08.md                          │
│  ← 作業が一区切りつくたびにAIが5行記録     │
│  転記済みの見出しには ✅ が付く            │
└───────────────┬───────────────────────────┘
                │ 年に1回、AIが1年分を凝縮（任意）
                ▼
┌─────────────────────────────────────────┐
│  年鑑/2026.md                             │
└─────────────────────────────────────────┘
```

**情報は下から上へ「圧縮」されていきます。** 日々の記録（日誌）→ テーマ別の知識（棚）→ 1年の要約（年鑑）。
新しい会話では一番上の目録だけ見れば関係する棚に案内してもらえるので、AIが読み込む量は最小限で済みます。

## ⚙️ 自動で回る仕掛け（ここが心臓部）

この仕組みが勝手に回るのは、**契約が2つだけ**だからです。

| 契約 | 意味 |
|---|---|
| `｜棚:◯◯` | 日誌の見出しに書く「この記録はどの棚へ行くか」の指定 |
| `✅` | 見出しに付く「棚へ転記済み」の印 |

```
## ✅YYYY-MM-DD サイトAのデザイン確定 ｜棚:仕事     ← 転記済み
## YYYY-MM-DD 短編小説の第2話プロット ｜棚:趣味・創作  ← まだ
```

AIは日誌に書き足す直前に、**見出し行だけを検索**します。`✅` の無い見出しが5件以上あれば、その場で棚へ転記します。

この設計だと、こうなります。

- **あなたは「整理して」と言わなくていい**（書く動作に整理が相乗りしている）
- **日誌が何ヶ月分たまっても、AIが読む量は増えない**（見出し行しか見ないので）
- **同じ記録が二度転記されない**（`✅` があるので）
- **何ヶ月サボっても取りこぼさない**（日付ではなく印で判定するので）

> 💡 最初のバージョンでは「週1回、AIに整理を頼む」という設計でした。これは**動きません**。
> 「週1回」を誰が始めるかが決まっておらず、日誌が溜まるだけになるからです。
> 時間で決めたルールは静かに壊れます。**必ず起きる動作に相乗りさせる**のが正解でした。

## ⏱ 5分セットアップ（手動でやる場合）

### ステップ1：`library/` をコピーする

このリポジトリの `library/` フォルダを、あなたの作業フォルダの直下にコピーします。

```
あなたの作業フォルダ/
├── library/
│   ├── 目録.md
│   ├── 運用ルール.md
│   ├── 棚/
│   ├── docs/
│   └── 日誌/
└── CLAUDE.md（または AGENTS.md）
```

### ステップ2：常時読み込みファイルにスニペットを貼る

`snippets/claude-md-snippet.md` の中の ```markdown ブロックの中身を、`CLAUDE.md`（Codexなら `AGENTS.md`、Cursorなら `.cursor/rules/`、ChatGPTならカスタム指示欄）に貼り付けます。

これが**唯一の常時ロード分**です。読む条件・書く型・整理の起動条件が全部この中に入っています。

### ステップ3：棚をあなた仕様にする

初期の4冊はあくまで例です。AIにこう言ってください。

```
library/目録.md と library/運用ルール.md を読んで仕組みを理解して。
そのあと私に3問だけ質問して、棚を私の実態に合わせて作り直して。
目録の表と棚の実ファイルは必ず一致させて。
```

**目録の表と実ファイルがズレると転記先が決まらず、自動化が止まります。** ここだけ注意してください。

### ステップ4（任意）：スラッシュコマンドを置く

Claude Code なら `commands/log.md` と `commands/tidy.md` を `.claude/commands/` にコピーすると、
`/log`（今の作業を記録）と `/tidy`（今すぐ整理）を手動でも呼べます。無くても自動で回ります。

## 📋 運用ルールの要約

詳しくは `library/運用ルール.md`。ここでは3行で。

1. **AIが、作業の区切りで日誌に5行だけ書く**（見出しに `｜棚:◯◯` を付ける）
2. **未転記が5件たまったら、AIが自分で棚へ転記する**（あなたは何も言わなくていい）
3. **棚は全文読まない。検索して必要な部分だけ読む**（これがコストと回答品質の両方に効く）

## 🔒 安全に使う

公開テンプレと、導入後に作られる個人用 `library/` は別物です。個人用 `library/` には、APIキー、トークン、パスワード、Cookie/セッション、`.env`や認証ファイルの中身、金融情報、住所・電話・メール、顧客の非公開情報、生ログを書かないでください。詳しい確認手順は [安全とプライバシー](library/docs/安全とプライバシー.md) と [複数AIで使う場合](library/docs/複数AIで使う場合.md) を参照してください。

## ❓ FAQ

**Q. プログラミングの知識は必要ですか？**
A. 不要です。すべて普通の日本語（Markdown）のテキストファイルです。

**Q. Claude Code 以外でも使えますか？**
A. 使えます。Codex・Cursor・GitHub Copilot CLI など、ファイルを自分で読み書きできるAIエージェントならそのまま動きます。ChatGPTやGeminiのチャットでも、libraryの中身を添付する形で応用できますが、「AIが自分で目録を見に行って必要な棚だけ読む」自動化はファイルを扱えるツールでこそ効きます。

**Q. AIが日誌を書き忘れることはありますか？**
A. あります。「作業が一区切りついた」の判断はAIに任せているので、100%ではありません。書かれていないと感じたら「ログ」と一言添えてください（`/log` コマンドを入れていればそれでも可）。書きさえすれば整理は自動で走ります。

**Q. 棚は4つ以上増やしてもいいですか？**
A. はい。`library/目録.md` の表に1行追記し、`library/棚/` にファイルを追加するだけです。ただし**目録の表と実ファイルは必ず一致させてください**（転記先の判定に使われます）。3〜5冊が選びやすい目安です。

**Q. 棚の記入例（サンプル）はどうすればいいですか？**
A. 各棚の「⚠️ ここから下はサンプルです」より下は例示です。AIはそこを事実として扱わないよう指示されていますが、自分の情報を書き始めたら消してかまいません。

**Q. 家族や仕事仲間と共有できますか？**
A. できます。ただしlibraryの中身には個人情報や機密情報を書きがちなので、共有・公開の前に必ず中身を確認してください。
