# 図書館の運用ルール（書く人＝AI、読む人＝AI）

この図書館は「日誌に書く → たまったら棚へ転記する → 棚から必要な分だけ読む」の3工程で回る。
3工程をつなぐ契約は**見出し行の `｜棚:◯◯` と `✅`** の2つだけ。これが崩れると自動整理が止まる。

---

## 1. 日誌の書き方（作業が一区切りついたら1回）

`日誌/YYYY-MM.md` の末尾に追記する。**見出しに転記先の棚名を必ず書く。5行以内厳守。**

```
## YYYY-MM-DD 〇〇の作業 ｜棚:仕事
- やったこと: 何をしたか一言で
- 成果物: ファイルの場所やURL
- 学び: 次に活かせる気づき
```

- `｜棚:` が無いエントリは整理で拾えず、永久に棚へ上がらない
- 棚名は**ファイル名から `.md` を取ったもの**をそのまま書く（棚の一覧は `目録.md`）
- 転記先が複数なら `｜棚:仕事,AI活用術`
- **`｜棚:` は見出し行の末尾に1回だけ。** タイトル部分にこの文字列を含めない
  （含めると転記先の判定が壊れる。読む側も見出し末尾の1つだけを転記先とみなす）
- 生ログ（会話全文やエラー全文）は書かない。要点だけ
- 雑談だけのセッション・5行にする価値がない作業は**書かなくてよい**

### 安全とプライバシー

- APIキー、トークン、パスワード、Cookie/セッション、`.env`や認証ファイルの中身、金融情報、住所・電話・メール、顧客の非公開情報は書かない
- 値や全文を記録せず、「APIキーを環境変数へ移した」「認証を設定した」のように完了事実だけを書く
- 誤って漏えいしたら、資格情報の無効化・再発行を最優先に行い、その後で履歴除去、Git除外設定、再発防止を行う。ファイル削除だけで完了扱いにしない
- 生ログ（会話全文・ターミナル全文・エラー全文）は書かない
- 詳しくは [安全とプライバシー](docs/安全とプライバシー.md)

### 書き手は1つだけ

- この `library/` に書き込むAIは1つに決める。同じ日誌へ複数のAIが同時に追記すると、重複と誤った `✅` が起きる
- 複数のAIを使うなら、未検品の記録は `library/` の**外**の staging に置き、検品済みだけを単一の経路で昇格させる
- 詳しくは [複数AIで使う場合](docs/複数AIで使う場合.md)

## 2. 転記マーク（整理との契約）

棚へ転記し終えた日誌エントリは、見出しの日付の前に `✅` を付ける。

```
## ✅YYYY-MM-DD 〇〇の作業 ｜棚:仕事
```

- 整理は「`✅` の無い見出し」だけを処理する。日誌が何ヶ月分たまっても読む量は増えない
- 二重転記が起きない（冪等）。整理を何度飛ばしても取りこぼさない
- 転記済みでも日誌の本文は消さない（時系列の生の記録として残す）

## 3. 整理の起動条件（ユーザーは何もしなくてよい）

**日誌に追記する直前に、その月の見出し行だけを検索する（`^## `）。`✅` の無い見出しが5件以上あれば整理する。**

整理を「週1回」のような時間で決めない。時間ベースは誰も起動せず、静かに壊れる。
「日誌を書く」という必ず起きる動作に相乗りさせるので、書けば必ず整理まで回る。

## 4. 整理の手順

1. 検索（Grep）で `日誌/` の **`20*.md` だけ**を対象に `^## ` 行を取得する（`README.md` はサンプルを含むので対象外。本文は読まない）
2. `✅` の無い見出しの行番号を使い、そのエントリの数行だけを読む。日誌全体は読まない
3. 見出しの `｜棚:` が指す棚へ転記・統合する
   - APIキー・トークン・パスワード・個人情報・生ログなどの禁止情報を検出したエントリは転記しない。値を表示せず利用者へ報告し、資格情報なら無効化・再発行を優先する
   - 転記先は `目録.md` の「棚の案内」表が正。棚を勝手に増やさない
   - `｜棚:` の指定が無いエントリは内容から判断して転記し、「指定漏れ1件」と報告する
   - 既存エントリと重複する内容は統合する（同じことを二度書かない）
   - 原本が別ファイルにあるものはコピーせず1行でリンクする
4. 開いた棚の中で今の事実と矛盾する古い記述があれば直す・消す（開いていない棚は見に行かない）
5. 転記できたエントリの見出しに `✅` を付ける。**これを忘れると次回に二重転記される**
6. 「転記◯件、改訂◯件」を1〜2行だけ報告する

## 5. 棚の読み方（開く側のルール）

- 棚を**頭から全文読まない**。まず検索で見出し（`^#{2,3} `）かキーワードを引き、該当セクションだけ読む
- 目録の「こういう仕事のときに開く」に当てはまらない棚は開かない
- 1つの仕事で開く棚は原則1〜2冊

## 6. 棚の書き方

- 1エントリ＝見出し＋数行。「いつ・何をした・どこにあるか・何を学んだか」
- **原本があるものはコピーせずリンクする**（例:「詳しい手順は 〇〇.md 参照」の1行）
- **棚に「書き方のヒント」を置かない**。書き方の正本はこのファイル。棚に置くと開くたびに読まされる
- ルールに昇格すべき学び（同じミスを2回した等）は棚ではなく常時読み込みファイル（CLAUDE.md / AGENTS.md）へ移す
- サンプルと本物を混ぜない。棚に残っているサンプルは事実として扱わない

## 7. 長期成長設計

- **時間の圧縮階層**: 日誌（日単位・生の記録）→ 棚（テーマ単位・整理済み）→ 年鑑（年単位・1ページ）。古い詳細は下の層に沈み、上の層だけ読めば全体がわかる
- **年1回の年鑑**（慣れてきたら導入）: 前年の日誌12ヶ月分を `年鑑/YYYY.md` に1ページで凝縮する。書き終えた年の日誌は読み返し対象から卒業（消さずアーカイブ）
- **目録は常に1枚**: 収まらなくなったら棚側を階層化し、目録には親項目だけ載せる
- **棚が300行を超えたら分冊**し、目録も更新する
- **ツール非依存・移設可能**: プレーンなMarkdownのみ。パスやツール名への依存は最小限に

## 8. 検索できない図書館は死んだ図書館

- ファイル名・見出しは普段使う普通の言葉で書く（後から検索して探せるように）
- 固有名詞は初出でフルネーム＋場所（ファイルパスやURL）を書く（「あれ」「例の件」禁止）
- 日付は必ず絶対表記（YYYY-MM-DD形式）。「先週」「昨日」は禁止（後から読むと意味が分からなくなる）
