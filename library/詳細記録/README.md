# 詳細記録の書き方

詳細記録は、会話履歴が消えても**別のAIが迷わず作業を再開できる状態**を残す場所です。会話全文や作業ログの保管場所ではありません。

## 作るかどうか

日誌を書くとき、次で判定します。

> この会話履歴が今消えても、別のAIが日誌だけで、判断理由・現在地・次の作業まで迷わず再開できるか？

- できるなら日誌だけ
- できないなら日誌と詳細記録を作り、日誌からリンクする

判定・リンク・安全の正本は `../運用ルール.md` です。

## ファイル名

`YYYY-MM-DD_検索しやすい作業名.md` を基本にします。ファイルはこのフォルダ直下に置き、件数が増えて探しにくくなった場合だけ大分類で分けます。

## 型

必要な節だけを具体的に書き、該当しない節は「なし」と埋めずに省略します。

```markdown
# YYYY-MM-DD 作業名

## 目的
この作業で達成すること。

## 開始時点
- 着手前に完了していたこと
- 前提・制約・基準

## 実施内容
1. 実際に行ったこと
2. 結果を確認したこと

## 重要な判断と理由
### 判断したこと
- 判断: 採用した方針
- 理由: その方針を選んだ根拠

## 試した案と却下理由
### 案の名前
- 結果: 試して分かったこと
- 却下理由: 採用しなかった理由
- 見分け方: 次に同じ思い込みをしないための兆候（書ける場合だけ）

## ユーザーからの重要な修正
- 当初の理解 → 修正後の要件・判断基準

## 現在地
- 完了: どこまで終わっているか
- 状態: 動作確認・承認・保留など

## 未完了事項
- 残っている作業と、止まっている理由

## 次にやること（ここから先は勝手に進めない）
- やってよいこと: 再開後に着手してよい作業。範囲を区切って書く
- やらないこと: 今回の範囲の外。ついでに直さない・広げないもの
- 終わったと言える条件: 何が確認できたら、この一手が終わりか
- 次に進んでよいか: 進めてよい ／ 相談してから ／ ここで止める
- やり直す条件: この前提が変わっていたら判断からやり直す（書ける場合だけ）

## 再開時に読むファイル
- `相対パス` — 読む理由

## 成果物
- `相対パス` または URL — 内容と状態

## 得られた知見
- 次回にも使える事実・判断基準
```

「次にやること」の4つ（やってよいこと・やらないこと・終わったと言える条件・次に進んでよいか）は、作業に続きがある場合は省略しません。次にどこまでやってよいかの境界が、ここにしか書かれていないためです。「やり直す条件」と「見分け方」は書ける場合だけで構いません。

## 書かないもの

- 会話全文、ターミナル全文、エラー全文などの生ログ
- 日誌や棚にすでにある要約の繰り返し
- 原本・成果物の全文コピー
- 再開に影響しない細かな操作の羅列
- 推測で補った背景や、項目を埋めるためだけの文章
- 「やってよいこと」を並べて次の作業範囲を広げること
- APIキー、トークン、パスワード、個人情報、顧客の非公開情報など `../docs/安全とプライバシー.md` で禁止されている情報

詳細記録は長さではなく、**現在地から次の一手へ迷わず移れるか**で完成を判断します。十分になったらそこで止めます。
